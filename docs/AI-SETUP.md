# AI 配置

AI 是可选功能。文献库、PDF 阅读批注、个人笔记、搜索和备份无需 AI 账户。当前可在“设置与数据”选择 Codex CLI、Ollama 或 OpenAI-compatible API。

新建空库默认关闭 AI。界面配置保存到自己的本地库；非空环境变量可能覆盖界面选择。

## 先选一种连接方式

| 方式 | 准备工作 | 推理位置 |
| --- | --- | --- |
| Codex CLI | 在自己的电脑安装 CLI，并自行登录可用账户 | 本机启动进程，模型推理联网 |
| Ollama | 启动自己的 Ollama 服务，安装可用模型 | 取决于填写的服务地址；本机服务可在本机推理 |
| 兼容 API | 自行提供服务地址、模型和所需密钥 | 取决于所选服务 |

选择当前账户或服务实际可用的模型。程序不会因为填了模型名就保证授权、额度或输出格式可用。

## PDF 相关的可选系统工具

论文对话需要 Poppler 的 `pdftotext` 提取 PDF 文字；旧短摘要也使用它，提取失败时可在有已保存摘要的情况下回退。PDF 选区公式 / Markdown 图像识别还需要 `pdfinfo` 与 `pdftoppm`。

PDF 阅读、普通笔记、新导读的 PDF.js 提取、想法讨论和笔记建议不依赖 Poppler。macOS 已安装 Homebrew 时可运行 `brew install poppler`；其他系统请使用自己的包管理器。安装后重新运行 `npm run doctor` 查看命令是否可用。

不在默认命令路径时，可指定可执行文件：

```dotenv
KB_PDFTOTEXT=pdftotext
KB_PDFINFO=pdfinfo
KB_PDFTOPPM=pdftoppm
```

## Codex CLI

在本机终端确认已安装并完成自己的登录：

```bash
codex --version
codex login
```

然后在“设置与数据”选择“Codex CLI”，填写可用模型或留空使用 CLI 默认值，点击“测试 Codex 连接”。测试会检查安装、登录并发起一个短请求；成功后保存设置。

连接测试会联网并使用账户额度，但不会读取文献或笔记，也不保存 AI 内容。测试成功只代表本次调用可用，不评价论文分析质量。

应用复用本机 CLI 登录，不要求把登录文件放入项目，也不会通过知识库备份分发登录凭据。每个使用者都需要配置自己的账户。

如果找不到 CLI，或系统中有多个版本，可在 `.env.local` 明确填写可执行文件路径：

```dotenv
KB_CODEX_BIN=
KB_CODEX_MODEL=
```

`KB_CODEX_BIN` 留空时，优先使用启动环境中可用的 Codex 应用 CLI 路径，再尝试 `PATH` 中的 `codex`。`KB_CODEX_MODEL` 留空时采用界面设置，再留空采用 CLI 默认值。修改 `.env.local` 后重启本地服务。

当前 Codex 集成依赖 CLI 的 `exec` 与实验性 `app-server` 动态工具协议；CLI 版本变化可能影响连接、流式对话、模型列表或本机历史读取。遇到不兼容时请记录版本和脱敏错误，不复制账户文件到问题报告。

## Ollama

先自行安装并启动 Ollama，确保计划使用的模型已经可用。在“设置与数据”中选择 Ollama，填写地址和模型名称。

默认本机地址为 `http://127.0.0.1:11434`。也可通过 `.env.local` 配置：

```dotenv
KB_AI_PROVIDER=ollama
KB_OLLAMA_URL=http://127.0.0.1:11434
KB_OLLAMA_MODEL=填写自己已安装的模型名称
```

模型下载、硬件资源和模型许可由使用者自行选择。若填写远程地址，材料会发送到那个服务；只有使用本机服务时，才能将推理视为本机执行。

## OpenAI-compatible API

在界面中选择兼容 API，填写基础地址和模型名。地址需包含该服务要求的路径（例如 `/v1`），应用会追加 `/chat/completions`。

密钥只放在本机后端环境变量中：

```dotenv
KB_AI_PROVIDER=openai-compatible
KB_OPENAI_URL=https://your-provider.example/v1
KB_OPENAI_MODEL=填写服务提供的模型名称
KB_OPENAI_API_KEY=
```

上面的地址是占位示例，不能直接调用。填写实际服务地址和自己的密钥后重启。不要将密钥写入网页地址、Markdown、截图或公开仓库。

本机服务可用 HTTP，远程服务使用 HTTPS。地址不得包含用户名、密码、查询参数或密钥。兼容 API 的能力、费用与授权以自己的服务为准；使用兼容接口不代表服务来自 OpenAI。

## 配置优先级

- `KB_AI_PROVIDER` 非空时覆盖界面选择；留空时由界面决定，`none` 强制关闭 AI。
- 环境中配置的默认模型优先于对应的已保存默认值。
- 论文对话与想法讨论可为本次新提问选择模型；改变选择不影响正在运行的请求和历史记录。
- “重试原提问”沿用原模型与提供方。提供方配置改变后，可以新建问题，或先恢复原配置再重试。

通常在界面配置即可。只有需要固定部署配置或填写后端密钥时，再使用 `.env.local`。

## 哪些材料会被使用

用户主动生成时，程序按功能组织本次材料，而不是默认发送整库：

- **论文对话**：显示实际读取的 PDF 页范围、字符数、历史消息数，以及明确加入的个人参考资料。
- **导读与比较**：使用主动选定的正文、补充材料或论文，保存阅读范围和来源信息。
- **想法讨论**：使用本次提问、沿用的已完成讨论和明确加入的资料快照。
- **笔记建议**：使用当前正文或选段，以及确认选择的关联上下文。
- **文献查找**：读取公开题录和有限摘要；它不等于阅读全文，也不自动下载或入库。收藏与下载由页面中的确认操作完成。

对远程 AI，这些材料会发送到相应提供方。Codex 虽在本机启动，模型推理仍需要网络并使用自己的账户权限与额度。不要把“数据保存在本机”理解成“使用远程模型时没有材料出站”。

AI 输出与个人正文分开保存；需要明确采纳、插入或追加才能成为笔记修改。AI 导读中的页码、原句和位置校验用于帮助回查，不保证推理或结论正确。

## 等待、停止与失败

论文对话与想法讨论会显示运行阶段、用时和活动详情，可以主动停止。服务器心跳与进程存活不能证明模型仍在推理。失败或停止时保存实际收到的正文，原提问和个人笔记继续保留。

可选环境变量：

```dotenv
# 流式论文/想法讨论：留空或 0 不设应用级总等待时限
KB_CHAT_TIMEOUT_MS=0
# 非流式 Codex 任务：默认 180000 毫秒
KB_CODEX_TIMEOUT_MS=180000
```

给 `KB_CHAT_TIMEOUT_MS` 设置正数会显式启用总时限。服务器退出、连接中断、上游服务或部署代理仍可能结束请求。导读、阶段整理、笔记建议和连接测试有各自的限制，不因流式聊天设置而变成无限等待。

Codex 文献工具支持多篇查询排队；本轮真实检索最多尝试 12 次，额度用尽后向模型返回提示，让它继续汇总已有结果。查询结果不是论文全文，未核实的文献应明确标出。

## 常见故障

- **基础界面能用，AI 不可用**：检查服务是否运行、提供方与模型名、账户权限和额度；基础功能可继续使用。
- **选择了模型但实际未生效**：检查 `.env.local` 或启动环境是否覆盖界面设置，修改后重启。
- **Codex CLI 能打开，但应用连接失败**：确认启动应用的进程能找到同一 CLI；必要时明确设置路径，重新做连接测试。
- **论文对话提示 PDF 文本解析不可用**：安装 Poppler 并确认 `pdftotext` 能被启动进程找到。PDF 阅读不受该命令缺失影响。
- **公式识别失败**：检查 `pdfinfo`、`pdftoppm`、PDF 是否加密及模型是否支持该功能；不会以纯文本猜测代替失败的图像识别。
- **回复格式不支持**：部分导读和建议要求结构化输出；模型或服务不满足约定时会报错，不覆盖旧结果。
- **换电脑后无法连接**：库备份不复制 AI 登录和密钥；需要在新电脑重新配置自己的服务。
